Easy to Check, Hard to Find

P vs. NP asks whether the speed of checking an answer is truly different from the speed of finding one. Try solving it yourself, then compare with how a computer does it.

Brute force runs for at most 6 seconds; if it hasn't found the answer by then, the total time is estimated from the measured speed. Each extra number adds just one step to verification, but doubles the number of combinations to search. To be precise, though, the hardness of Subset Sum comes from the number of digits. When the numbers are small, DP only needs to fill n × target cells, so it solves the problem easily (pseudo-polynomial time). Each extra digit multiplies the target by 10, and the table grows 10-fold with it. There is also a cleverer O(2^(n/2)) algorithm than brute force, but it is still exponential time. Whether a polynomial-time algorithm that works in every case exists has not been settled, and that is exactly the P ≠ NP question.

3. The Moment 3-SAT Turns into a Graph

This is Karp's reduction. Each literal of the formula becomes a node, and nodes in different clauses are joined by an edge unless they contradict each other (x and ¬x). If you pick one node per clause so that all of them are connected to each other, you have found a way to make the formula true. Click the nodes to choose them yourself.

It works in both directions. If an assignment satisfies the formula, you can pick one true literal per clause to form a clique of size K (the variable buttons). Conversely, if there is a clique of size K, setting those literals to true satisfies the formula (contradictory pairs have no edge, so they never clash). So if there is no clique, the formula is unsatisfiable. Because this transformation finishes in polynomial time, a fast way to solve Clique would also solve 3-SAT fast. That is what NP-complete means.
